# LLM 아키텍처의 한계점 (종합)

> ⚠️ **출처 주의**: 이 페이지는 `raw/` 자료를 Ingest한 결과가 아니라 작성 시점(2026-10-12)의 **일반 지식**으로 쓴 초안이다. `CLAUDE.md`의 "raw 출처 명시" 규칙의 예외로 사용자가 승인했다. 수치·최신 동향은 단정하지 않고 `[확인 필요]`로 표시했으며, 관련 논문을 `raw/papers/`에 넣고 Ingest하면 이 페이지를 출처 기반으로 갱신해야 한다.

범위: 트랜스포머 기반 자기회귀(autoregressive) LLM을 기준으로 한다.

## 1. 연산·메모리 구조의 한계
| 한계 | 설명 | 대표적 완화책 (각각 trade-off 있음) |
|---|---|---|
| 어텐션의 시퀀스 길이 제곱 비용 | self-attention의 연산량이 입력 길이 n에 대해 O(n²) | FlashAttention(정확한 어텐션의 I/O 최적화), 희소·선형 어텐션, 상태공간모델(예: Mamba) 계열 / 품질 저하 가능성 `[확인 필요: 최신 모델별 비교]` |
| KV 캐시 메모리 | 추론 시 토큰 수에 비례해 캐시가 커져 긴 컨텍스트·다중 사용자 서빙의 병목 | MQA/GQA, 캐시 양자화·압축 |
| 순차적 디코딩 지연 | 토큰을 하나씩 생성하므로 출력 길이만큼 순차 단계 필요 | 추측 디코딩(speculative decoding), 배치 최적화 |
| MoE의 메모리 | 활성 파라미터는 적어도 전체 전문가를 메모리에 올려야 함 | 전문가 병렬화·오프로딩 |

## 2. 긴 컨텍스트의 한계
- 컨텍스트 창이 길어져도 **실제로 잘 활용하는 것**과는 별개다. "Lost in the middle" 연구(Liu 등, 2023)는 중간 위치 정보의 활용도가 떨어짐을 보고했다.
- 최신 모델에서 이 현상이 어느 정도 해소됐는지는 `[확인 필요]`.

## 3. 학습 목표에서 오는 한계
- **환각(hallucination)**: 다음 토큰 확률을 맞추도록 학습되어 "그럴듯함"과 "사실성"이 구분되지 않을 수 있다. 검색 증강(RAG)·도구 사용·사실성 평가로 완화하지만 완전히 제거되지는 않는다.
- **정적 지식**: 학습 시점 이후의 정보를 모르며(지식 컷오프), 지속적 학습 시 기존 능력이 망가지는 *파국적 망각*(catastrophic forgetting) 위험이 있다.
- **추론·계획**: 다단계 추론, 조합적 일반화, 정확한 산술·기호 조작에서 오류가 나는 경우가 보고된다. 사고 과정(chain-of-thought)·추론 시간 연산 확장으로 개선되나, 한계의 정도는 모델·과제에 따라 달라 `[확인 필요]`.
- **토큰화 의존성**: 서브워드 토큰화 때문에 글자 단위 과제(철자 세기, 역순 등)에 취약할 수 있다.

## 4. 스케일링·운영상의 한계
- 학습·추론 비용(연산, 에너지, 비용)이 모델·컨텍스트 규모에 따라 크게 증가.
- 고품질 학습 데이터 고갈 가능성("data wall") 논의가 있으나 시점·규모는 `[확인 필요]`.
- 내부 동작의 **해석 가능성**과 신뢰성 보증이 어렵다 (안전성·감사 이슈).

## 5. 종합 관찰
1. 많은 한계는 **트랜스포머 구조 자체(비용)** 와 **학습 목표(사실성·추론)** 두 축으로 나뉜다. 전자는 하드웨어·알고리즘 최적화로, 후자는 외부 도구·검색·추론 시간 연산으로 주로 보완한다.
2. 완화책은 대개 비용·품질·복잡도 사이의 **교환**이다. 구조 대체(SSM 등)가 트랜스포머를 전면 대체했는지는 `[확인 필요]`.
3. 위키 내 다른 영역과의 연결: 기업가정신 자료의 [[타당성 분석]] 관점에서, LLM 기반 제품은 [[제품 서비스 타당성]](수요·바람직성)뿐 아니라 위 한계에서 오는 *기술·비용 타당성*도 점검해야 한다. *(이 연결은 작성자의 해석이며 강의 자료가 직접 다룬 내용이 아님 — [확인 필요])*
